# 山泽 C4D 插件开发标准

**中文名称：** 山泽 C4D 插件开发标准

**用途：** 按山泽插件库格式开发、更新和打包 C4D 插件，附模板及本地预检。

**调用示例：** 使用 $chinese-skills:shanze-c4d-plugin-dev 开发一个 C4D 插件，并交付通过上传预检的 ZIP。

`<SKILL_DIR>` 从实际加载的 SKILL.md 所在目录解析，示例中的项目、服务器及源码路径由使用者提供。预检需 Python 3.11+ 与目标山泽插件库源码；市场不附公司服务端、发布密码或 C4D 工具包。

目标是能被山泽插件库接收、安装并正确执行的插件 ZIP。新工具默认同时交付可维护源码、`plugin.json`、上传 ZIP 和验证记录；用户明确指定其他分发方式时以其请求为准。

## 开发前

1. 读取当前项目规则，确定源码、打包输出及测试数据的授权位置。Skill 不授予上传、改服务端校验器、写 C4D 安装目录或重启 C4D 的权限。
2. 阅读 [上传标准](references/upload-standard.md)，核对目标部署的 `README.md`、`CompanyPluginManager/pm_core.py`、`server/server.py`。预检通过 `--registry-root` 指定这三个文件所在的项目根目录，未指定时仅尝试当前目录及其 CompanyPluginManager 子目录；未找到则请求用户提供目标源码路径。不同版本规则不一致时，说明差异并针对目标部署验证，不修改服务端限制来迁就插件。
3. 确定目标 C4D 版本、插件 `id`、版本、类型和实际命令 ID。更新沿用原 `id` / `command_id` / `kind`。读取公开 `/api/catalog` 检查冲突，离线时报告尚未检查线上目录。开发 ID 不是公司持有的 Maxon ID，不宣称全局唯一。

## 实现

- 普通命令型 Python 工具优先使用 `kind: "python"`。复制 [Python 模板](assets/python-tool/) 到当前项目，填写真实身份和 ID。模板的 `command_id: null` 故意不能通过预检；示例功能是给所选对象追加名称标记，需替换为当前需求。
- Python 包提供 `entry.py` 和明确的 `execute(doc)`，返回 `False` 表示失败。管理器从文件路径将入口加载成独立模块，因此入口不要依赖包相对导入，也不要假设其目录自动加入 `sys.path`。模板通过插件 ID + 版本创建依赖命名空间，内部模块可相对导入；资源路径从 `__file__` 解析，不写开发电脑绝对路径。
- 使用传入的 `doc`；C4D 对象及 UI 操作在主线程执行，场景修改提供 Undo。导入模块不自动改场景、不自动弹窗、不启动工具。纯计算尽量与 C4D 界面分开，便于测试。
- Python 命令由管理器注册，入口无需自行调用 `RegisterCommandPlugin`。真正需要原生启动注册的组件采用 `kind: "native"`，按上传标准核对注册 ID、启动与更新限制。
- 包内放齐依赖及资源。涉及生成器、旧场景或版本隔离依赖时，验证保存重开及跨电脑使用；描述真实依赖，保留兼容旧对象的数据 ID 和入口。

## 打包与预检

`<SKILL_DIR>` 代表当前实际加载的 Skill 文件夹；用本任务授权目录替换示例路径。输出 ZIP 放在源目录外。脚本只读目录、打包并在输出目录内创建临时沙箱，不执行待上传插件，不调用真实上传接口。

```powershell
python -B "<SKILL_DIR>/scripts/preflight.py" --source "<当前项目>/tool" --output "<当前项目>/dist/my-tool-1.0.0.zip" --registry-root "<插件库源码根目录>" --catalog-url "<已配置的插件库服务地址>" --c4d-version 2026400 --report "<当前项目>/dist/preflight.json"
```

- 已有 ZIP：用 `--zip "完整路径.zip"` 替代 `--source` / `--output`。
- 离线目录：用 `--catalog "catalog.json"` 替代 `--catalog-url`，文件为原始 `{ "schema": 1, "plugins": [...] }` 格式。
- 输出存在时拒绝覆盖；有意修改包内容后递增版本，输出新文件。
- 预检复用目标插件库的 `inspect_package`、`Registry.publish`、`Client.install`，检查实际规则、当前目录冲突、Python 语法与沙箱安装，给出 SHA256。没给目录参数时，仅证明离线结构与安装预检，不能声称线上 ID 无冲突。历史同版本 ZIP 是否存在最终由服务端判断。

## 验证与交付

分别记录以下结果，避免把格式预检当作运行验证：

1. **格式及安装预检**：脚本退出码 0，记录校验器路径、SHA256、目录冲突检查状态和目标 C4D 版本。失败先修插件或清单，再预检。
2. **C4D 功能验证**：隔离文档测试正确输入、空选 / 错误输入、真实输出、Undo；按需测试保存重开与旧版本升级。入口能直接执行不等于命令已注册。
3. **正式注册验证**：正式安装启动后检查管理器“使用”、公司菜单、命令管理器 / Shift+C。脚本环境无法完成注册时列为未验证，不重启未保存的 C4D。

交付列出源码、ZIP、插件身份与兼容范围、预检报告、C4D 实测结果及剩余限制。适用运行验证缺失时使用 `IMPLEMENTED_BUT_UNVERIFIED`。只要求开发和打包时不自动登录或上传；明确授权发布后才以管理员网页发布密码上传通过预检的 ZIP，员工下载免密码。
