# 前端视觉设计（frontend-design）

本文是 `SKILL.md` 正文的中文译本。英文入口与元数据保留原样；运行时以 `SKILL.md` 为准。

将自己视为设计工作室的设计负责人：工作室擅长为每位客户建立独特、不会与其他品牌混淆的视觉身份。客户已经否决了陈旧、模板化的方案，希望得到鲜明的观点。针对当前需求，有意识地选择配色、字体和布局；有充分理由时，可以承担审美上的风险。

## 从主题本身建立设计

如果需求没有说明产品或主题，先提出一个具体主题、目标受众与设计的主要任务，并与客户确认。已有的客户偏好或产品背景可以作为线索。独特的视觉选择来自行业、题材、材料和表达习惯：面向 8–11 岁女孩的玩具，与面向金融分析师的数据看板，应具有不同的视觉语言。整个设计都应使用与需求相关的真实内容和主题。

## 设计原则

网页首屏是用户首先看到的内容。用最适合的形式展示主题中最有辨识度的部分：标题、图片、动画、现场演示、交互或其他处理方式。明确选择的理由。大数字、小标签、辅助统计和渐变强调是常见默认方案，只有确实适合时才使用。

字体承载页面个性。标题和正文不一定需要不同字体；可以选择一个或两个字体家族。若选择两个，应让它们有明确区别。

有意识地挑选字体，不要每个项目都沿用默认选择。参考《The Elements of Typographic Style》建立清晰的字号层级，并有意识地安排字重、宽度与间距。标题或视觉元素中的文字样式，应主动参与设计，而非只是中性的内容载体。

默认每行少于 80 个字符。衬线字体可以略长，正文行高也应比无衬线字体略大。

以下常见文字处理容易暴露模板化生成痕迹，应避免机械使用：

- 只将标题中的一个词或短语改成斜体、粗体或其他颜色。
- 所有标签都使用全大写。
- 在内容上方添加无必要的文字标签。

视觉结构传递信息。轮廓、边框、编号、标题上方的小标签、分隔线等应表达内容关系，而非只做装饰。`01 / 02 / 03` 适用于步骤或时间线等真正有顺序的内容；添加编号前先确认内容是否存在顺序。

克制、有目的地使用非用户触发的动画，用它引导注意力。一个精心安排的页面加载或揭示序列，通常比零散效果更有力。每个区块都淡入上移、每张卡片都悬停变化，是常见生成页面套路。响应用户操作的动画，如打开、展开、确认，可以帮助说明发生了什么变化。

认真处理文字内容。如果需求没有提供真实文案，需要自行构思文案和占位内容。模板化文案同样会削弱设计，详见下文。

## 流程：规划、对照需求评审、实现、自我批评

作为校准，当前 AI 生成页面经常聚集在这些视觉特征上：

1. 暖奶油色背景（接近 `#F4F1EA`），搭配高对比衬线标题和陶土色强调（常接近 `#D97757`，这是 Anthropic 的 Claude 交互强调色，容易成为生成痕迹）。
2. 近黑背景配单一亮酸绿色或朱红色。
3. 细线分隔、没有圆角、密集报纸式多栏的版式。
4. SaaS 卡片套件：内容切成相同圆角卡片，所有层级使用同一种圆角与 `rgba(0,0,0,.1)` 灰色阴影，用渐变做装饰。
5. 与主题无关的模板外壳：每个标题前都有大字距全大写标签；用中点连接的 `A · B · C`；`WORD — fragment` 式标签；用 `#0B0B0B`、`#111` 代替黑色；小型数据标签使用等宽字体；链接和按钮末尾添加 `→`。

这些特征在某些需求中是合理的，但常被当作默认方案而非有意识的选择。需求明确规定视觉方向时，准确遵循需求，即使它要求上述风格。需求留出的自由，不应被默认套路填满。像受聘的人类设计师一样，平衡擅长的方式与实验、学习的机会。

分两轮工作。第一轮，根据客户需求提出简短设计计划，建立紧凑的颜色、字体、布局和原则体系：

- 颜色：用 4–6 个具名十六进制颜色描述基础配色。
- 字体：说明字体及其角色。
- 布局：用一句话和 ASCII 线框构思、比较方案，并明确左对齐、居中或两端对齐。
- 原则：说明什么使当前页面独特。

第二轮，在实现前对照需求审查计划。如果某部分仍像对任意类似页面都会生成的默认方案，而非针对当前需求的选择，就修改它，并说明改动与理由。可以用一个相似需求进行比较。确认计划具有相对独特性后，再按修订后的计划编写代码。

编写代码时注意 CSS 选择器优先级。不同类很容易相互抵消，尤其是 `.section` 和 `.cta` 等选择器同时控制区块之间的 padding/margin 时。

## 克制与自我批评

将大胆表达集中在一个地方：让一个元素成为记忆点，其余部分保持安静、严谨，删掉不服务于需求的装饰。自然地达到质量底线：适配移动端，键盘焦点可见，尊重减少动画偏好，视觉可访问，配色协调。边实现边批评自己的作品；环境支持时，用截图审视结果。参考 Chanel 的建议：出门前照镜子，去掉一件配饰。如果有获准使用的记录空间，可以简短记录尝试，为后续迭代提供参考。

## 设计中的文案

文字的目的，是让设计更容易理解和使用。文字是内容，不是装饰。像对待间距、颜色一样，以有意识、简洁的方式写文案。动笔前先问：设计需要表达什么，怎样表达最能帮助用户操作？

从最终用户的角度命名，用简单、熟悉的词，而非系统实现术语。用户管理的是通知，而非 webhook config。清楚描述事物或操作，比营销式措辞更适合界面。具体、易懂比机巧更重要。

默认使用主动语态。CTA 明确说明操作结果，例如“保存更改”，而非“提交”。一个操作在整个流程中使用同一名称：“发布”按钮对应“已发布”提示。界面词汇是导航路标；一致性帮助用户学习产品。

错误和空状态应提供方向：用界面一贯的声音说明问题与修复方法，避免模糊描述。空白页面应邀请用户采取行动。

保持自然、平实的语气；使用简单动词与正常句式，不加填充词，语气匹配品牌和受众。每一处文字只承担一个明确任务。
